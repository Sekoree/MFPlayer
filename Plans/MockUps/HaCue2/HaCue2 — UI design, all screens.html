HaCue2 · UI design · all screens · revision 3

A cue player that owns its whole window

HaCue2 is the cue player leaving HaPlay and becoming its own application. Revision 2 applies your screen-by-screen notes: the app opens in editing mode, the permanent output strip is gone (its information moves to a summonable Output info drawer and Diagnostics), the right panel tabs between Cue properties and Lists & groups at its bottom edge, and the project-owned audio channels are now called logical outputs everywhere.

Status revision 3 · rounds 1–2 applied · per-screen decisions settled Date 2026-08-01 Basis rev-2 study (preferred) + extraction plan + your notes on r1 Companion HaCue-Extraction-And-Project-Audio-Patch-Plan.md

What changed from revision 1 - your notes, applied

  • Opens in editing mode. Show lock still exists as an optional latch in the title bar, but it is never the launch state and it never gates GO.
  • The always-on strip is gone. Program meters, line chips and bay counters live in an Output info drawer toggled from the status bar (hidden by default), with the deep numbers staying in Diagnostics. One Diagnostics button, in the title bar - the duplicate is deleted.
  • Right panel gets bottom-edge tabs: Cue properties | Lists & groups. The active-cues panel keeps its own space below the tree and no longer carries the scope picker.
  • “Logical outputs” is the UI name (your call on cross-cutting #1). Cue sends go to logical outputs; the patch maps logical → device.
  • No arming gates on playback - GO, preview and audition always work in edit mode. What remains is one question about external inputs (MIDI/OSC/schedules/timecode), moved to the open-questions section with a concrete proposal.
  • Custom fade curves - every curve picker gains drawn thumbnails plus a custom option backed by a curve editor (screen 04); playlist groups get crossfade presets and per-transition overrides.
  • Timeline: undockable into its own window; volume/opacity become addable effect lanes per cue (hidden until added); groups collapse, move and take effects as a whole.
  • Preflight is renamed “Project status”, Notes/Script unify to a single Note tab, recording filename patterns get an insert-token dropdown, and Audio/Video each gain an Audition tab feeding a dedicated preview device/output combo.
  • Compositions lose the visualizer flag - visualizer is purely a cue type. A composition owns exactly: size, frame rate, idle image, and its per-output mapping (splitting + mesh warp).
  • Targets splits into tabs (Action endpoints · Trigger inputs · Remote API), the Remote API tab listing its actual endpoints.
  • No built-in HaPlay importer. Clean start; migration becomes a companion tool later. The launcher loses the import door.
  • Settings: full inventory of every pane in both scopes, auto-renumber on by default with a “new project defaults” group in application scope, and Diagnostics' event list is now literally the Microsoft.Extensions.Logging feed with a selectable level.

01 · Window

Launcher

Approved in round 1; two changes. The HaPlay import door is gone - clean start, migration is a possible companion tool later, so the launcher stops promising it. And projects now open straight into editing mode. Recovery stays inline above the recents, and “This machine” keeps running the cheap device checks before any project is chosen.

Resolved from round 1

  • No HaPlay importer. Removed. If migration is ever needed, it's a companion converter producing a .hacue2proj, built later, no priority.
  • New project seeding: kept, and wired to the new-project-defaults settings group so the first sound is never silence.

02 · View

Cues - the main view

The launch state: editing, unlocked, everything live. The chrome carries exactly one Diagnostics button (title bar). The right panel is the cue editor, and its bottom edge tabs between Cue properties and Lists & groups - scope switching and property editing share the column, never the screen's bottom. The active panel below the tree handles many simultaneous cues: groups aggregate their sounding children, cues from other lists carry the list name, and nothing about the current scope can hide a sounding cue.

Where the strip went: the Output info drawer

Program meters, line chips and bay counters were useful but didn't earn permanent screen space. They now live in a drawer summoned from the status bar (or F9), sliding up over the active panel and staying until dismissed. The status bar keeps a one-token summary at all times - ● outputs ok going amber/red is the tap on the shoulder; the drawer is the glance; Diagnostics is the investigation. Pop-out to a window is available for a second monitor.

Resolved from round 1

  • One Diagnostics button - title bar only; the drawer links nowhere, the status bar issue count opens Project status.
  • Program / Lines / Bay off the permanent UI - drawer + status-bar summary as above.
  • Lists & groups moved to the right panel's bottom tabs (see 03 for it active).
  • Note replaces Notes/Script - one tab, one name, on every cue kind.
  • Loads editing. The Lock chip is the old show mode as an opt-in latch: read-only document, GO untouched. Whether it stays at all is an open question at the end.

Decided

  • The drawer overlays the active panel - content never shifts when it opens.

03 · View

Cues - scoped to a group

Your expected shape - a playlist of songs where each song is a group carrying dozens of lighting, projection and patch cues - is 400–600 rows flat. So the tree scopes: the right panel's Lists & groups tab lists every cue list and every group as a selectable root; picking one limits the main view to that subtree, with the breadcrumb as the way out. The scope is a view filter, never a transport boundary: GO fires the show's next cue regardless, and the active panel always shows everything sounding, in or out of scope.

Resolved from round 1

  • Lists & groups relocated from the active panel to the right panel, tabs on the bottom edge, switching against Cue properties.
  • No arming, no gates - playing from edit mode is always possible; the r1 “arms disabled while editing” rule is deleted.
  • Status Messages / Project status: the status bar's issue counter opens the renamed Project status view (screen 14) - it is exactly a collector of errors and warnings.

Decided

  • Selecting a cue does not flip the panel - Lists & groups stays put while you browse. When you switch back to Cue properties yourself, it opens in the no-selection state (empty, “select a cue to edit”), not on a stale cue; clicking a cue from there populates it.
  • Double-clicking a group does not scope to it. Scoping happens only through Lists & groups; double-click stays free for standby/open gestures.

04 · Component

Inspector tabs & the fade-curve editor

Tab set per cue kind, selected tab remembered per kind, as approved. New here: every curve picker in the app shows drawn thumbnails of what each fade actually does, and the last option is always custom - opening a small editor where you drag points on the same visualization. One control, used for fade-in, fade-out, crossfades and patch-cue fades alike. Playlist groups gain crossfade presets with a per-transition override.

Resolved from round 1

  • Fade visualizations - thumbnails on every picker, doubling as the custom editor.
  • Playlist crossfades - preset chips (cut · 0.5 · 2 · 4 · custom) with good defaults plus per-transition overrides on the child cue.

  • Patch cues keep the inline “also change” list alongside snapshot recall - the long-term-correct shape ships from the start.

05 · Component

Timeline - dockable sheet, effect lanes, group handling

Still a bottom sheet by default - but with an Undock ↗ button that lifts it into its own window (remembering which mode you last used). Envelopes stop being a fixed overlay: volume, opacity and OSC/MIDI ramps are effect lanes you add per cue, hidden until added, collapsible after. Groups behave as objects: a group row collapses its children into one span-clip, drags as a whole, and accepts effect lanes of its own that scale everything inside.

Resolved from round 1

  • Undockable - sheet by default, own window on demand, mode remembered.
  • Envelopes as addable cue-property effects - volume/opacity/ramps are lanes you add and hide, not a permanent overlay. This is also the model for the planned OSC/MIDI outbound ramps.
  • Groups as wholes - collapse/expand, move as one, group-level effect lanes.
  • No strip, one Diagnostics button.

Decided

  • Child effects override group effects. When a group carries the same effect kind as a child, the child wins and shows a warning badge (“overrides group volume”) so the shadowing is never invisible.
  • One envelope concept, two editors - the effect-lane model replaces the media cue's separate VolumeEnvelope; the inspector and the timeline edit the same data.
  • Disabled children render hatched with struck labels (as now drawn) - unambiguous at a glance, unlike ghosting.

06 · View · the headline feature

Audio - logical outputs

The Audio view keeps its four panes - now Logical outputs · Patch · Devices · Audition. This is the first: the project's audio vocabulary. A logical output is a named channel (optionally shown as a stereo pair) that exists whether or not any hardware does; cues send to these and nothing else, and the show file never contains a device name. Selecting one shows who feeds it, where it goes, and its level - the effective route seen from the middle.

The two failure states this screen exists to catch are both on it, in colour: Orchestra (amber) is patched to hardware but no cue feeds it - a dead channel wasting an output; Lobby (red) is fed by cues but patched to nothing - sound that would silently vanish. HaPlay could not even express the second; here it's a first-class, visible, deliberate state, because “patched to nothing on this machine” is exactly what a show on tour looks like the day before the venue.

Resolved from round 1

  • “Logical outputs” is the UI name, used everywhere: sends, patch, status messages, this table. The model keeps LogicalAudioChannel; the model word never reaches a label.
  • “Pin to strip” became “Meter in summary” - with the strip gone, this flag picks which meters appear in the Output info drawer's compact row and the status-bar health token.

Decided

  • Per-logical-output trim is dropped - patch-cell gains are the only project-side gain stage. (The Level column and trim field are gone from this screen.)
  • Delete cleans up automatically - removing a logical output strips its sends from every cue as one undoable edit; no refuse-while-fed gate.
  • Named Output Groups are v1. A group (“Main”, “Fold”, the 🔗 column) links its members for editing: changing one member's patch-cell gain or mute applies the same delta to the other members' corresponding cells, and send grids show grouped columns with the same linked-delta behaviour. A stereo pair is just a two-member group. Grouping affects editing and display only - the mix math stays per-channel.

07 · View

Audio - patch matrix & snapshots

Approved in round 1 - carried over with the rename. Logical outputs across, device channels down, gain in the cells; the only place virtual meets physical. Gain and mute edit live; snapshots are named, partial patch states recalled by patch cues or by hand.

Decided

  • Solo-to-audition is always allowed - it plays through the audition monitor path, so it never interrupts the program mix and never appears in the Active list. “Solo” here means “listen to what this line carries”, not “mute everything else”.
  • Cell interaction confirmed: click toggles at unity, drag adjusts gain, right-click mutes.

08 · View

Audio - devices & audition

Devices as approved, with the recording pattern gaining an insert-token dropdown and a ? help popover listing every token with an example rendering. The preview/audition configuration leaves this pane and becomes a proper Audition tab - the same control appears in the Video view, because an audition rig is one thing: an audio device plus a video surface. Every cue's context menu gets Preview on audition outputs, playing it into that rig without touching the patch or the program bus.

Resolved from round 1

  • Pattern help - insert-token dropdown plus “?” listing tokens with a rendered example.
  • Dedicated Audition tab in Audio and Video (same control, duplicated), configuring an audio device + video out combo; cue context menu gains “Preview on audition outputs”.

Decided

  • Audio lines are project-owned - they travel with the show, go absent on other machines, and relink on arrival.
  • Mix-rate changes take an explicit “Apply & restart audio” - never a silent rebuild.
  • Per-line effects inserts deferred. Visualizer cues tap their audio feed from the program bus, upstream of any per-line insert, so deferring costs the visualizer nothing.

09 · View

Video - compositions & outputs

Two corrections from your notes. First, the visualizer flag is off the composition - that was HaPlay residue. A visualizer is purely a cue type; it appears on a canvas the same way any media cue does, as a placement, and all its settings live on the cue. A composition owns exactly four things: size, frame rate, idle image, and its per-output mapping (splitting + mesh warp - which live on the output binding, next screen). Second, the tab order is now Compositions · Mapping · Outputs, since mapping is the stage between the two.

Resolved from round 1

  • No visualizer on compositions. Visualizer is a cue type; its placement is just another layer. Composition = size + rate + idle image, full stop.
  • Idle image kept, as a composition property (per-output idle removed to avoid two idle concepts - flag if you wanted it per output instead).
  • Per-output mapping surfaced in Outputs - the Map column and the on/clean toggle: same composition, warped to Projector A, clean to Lobby TV and NDI.
  • Tab order Compositions · Mapping · Outputs.

Decided

  • The canvas is a second editor for cue data - placements edited here edit the cue, under the same undo journal.
  • Idle images exist at both levels: per output as a fallback, with the composition's idle image taking precedence when set (the “Idle fallback” field on the output).

10 · View

Video - output mapping

Now the middle tab, matching its place in the chain: composition → mapping → output. The header carries an output picker, because mapping is always of one output - Projector A gets the two-section warp below while Lobby TV keeps a clean feed of the same composition. Section list stays permanent on the left; source pick and output placement sit side by side.

Decided

  • Mesh warp first; corner-pin stays reserved in the model.
  • Test pattern is v1 - the per-output grid toggle ships with mapping.
  • All three input modes: drag with the mouse, numeric x/y/w/h entry, and arrow-key nudging of the last-clicked point for fine adjustment.

The wire monitor stays on every tab (filtered to that tab's traffic), because “did it actually send/arrive” is the question on all three. Trigger inputs drawn first; the Remote API tab follows with what it gains from the space: its actual endpoint list.

Resolved from round 1

  • Split into tabs - Action endpoints · Trigger inputs · Remote API; monitor per tab, filtered to that direction.
  • Remote API tab shows its endpoints, with live call counts and a self-documenting root.

Decided

  • Continuous-controller bindings to parameters (cc → master trim etc.) are v1, not just note→cue firing.
  • Endpoint test messages are configurable per endpoint - each action endpoint stores its own test payload.

13 · View

Settings - project scope

Journaled, undoable, travels in the file - as approved. Auto-renumber shows its inheritance: on by default because the app default says so, still switchable per project. Open mode now defaults to editing everywhere, so the pane's first row is only there for the show that wants to boot locked.

Decided

  • The overridable set is frozen for now at panic fade, remote API, hotkeys.

14 · View

Project status (was “Preflight”)

Renamed per your note - it is a collector of the project's errors and warnings, each with the fix action attached: missing media, unfed or unpatched logical outputs, absent devices, dead jump targets, past schedules. Reached from the status bar's issue count, the settings nav, and the launcher. Relink and consolidate live here because they are what fixing usually means. Headless twin: hacue2 --check show.hacue2proj, same checks, exit code 1 while errors remain.

Decided

  • Severity table confirmed: unpatched-but-fed = error; patched-but-unfed and absent devices = warnings.
  • The flag is inverted: outputs can be marked required. A required output that is absent is an error; unmarked outputs absent are warnings. This says “the show cannot run without the main PA” instead of asking every optional output to excuse itself.

15 · Window

Diagnostics

Own window, remembers its screen, meant to sit on a second monitor while operating. One change from round 1: the events panel stops being its own collector - it is a live tail of the Microsoft.Extensions.Logging pipeline, the same sink the file log uses, with a level picker. One logging system, two readers.

Resolved from round 1

  • No second logging system - the panel tails Microsoft.Extensions.Logging with a selectable minimum level; the file log stays the archive, the window is a tail.

Round-2 decisions

Round 1's cross-cutting questions were settled by your notes (logical outputs, tabs, no importer, one undo journal, no strip); the four that revision 2 raised were settled in review. All owner decisions, recorded here so no screen reopens them:

Decided in round 2 review

  • External input: one master toggle. The old Triggers/Schedules/Chase arms - the gates on the three ways a cue fires without a keypress (MIDI/OSC/hotkey bindings, wall-clock schedules, MTC chase) - collapse into a single External input on/off in the transport. Per-source enables live in Targets; off when a project opens (project setting); never gates GO.
  • Output info: drawer + pop-out. Hidden by default, status-bar toggle or F9, slides over the active panel, poppable to its own window for a second monitor.
  • Lock latch stays - one title-bar chip, opt-in only: read-only document, destructive commands disabled, GO untouched. Never the launch state.
  • Row click is a per-project setting (Show behaviour · “Clicking a cue row moves standby”), default off: single click view-selects, double-click or ↑/↓ Stby moves standby. Shows that want QLab-style click-to-target flip the setting.

Decided in round 3 review

  • Output Groups are v1 - named, linked-editing groups of logical outputs (see screen 06 for the spec); a stereo pair is a two-member group.
  • Multi-list transport is v1. Every cue list keeps its own standby/playhead in model and UI: the transport acts on the selected list, each list remembers its position, and per-list GO becomes addressable by hotkeys, triggers and the remote API (POST /lists/{id}/go). This supersedes the old “single playhead with model insurance” resolution. The transport row and Lists & groups need a dedicated drawing pass for it - queued for revision 4, and the extraction plan carries the scope change.
  • Panel behaviour refined (screen 03): selection never auto-flips the right panel; Cue properties reopens in the no-selection state.
